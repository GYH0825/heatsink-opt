## 二、技术概述

本项目面向散热器热设计，把「物理仿真 + 自适应搜索 + 大模型智能体编排」三层打通：

1. **物理仿真**：自研二维稳态热传导求解器，输出最高结温 `T_max` 与结到环境热阻 `R_th`；
2. **优化求解**：在结温 ≤ 85 °C、质量 ≤ 150 g、翅片厚/基板厚 = 2.0 mm 等约束下，
   用自适应邻域搜索寻找热阻最低的几何设计，固定随机种子保证结果可复现；
3. **智能体编排**：以 Agnes Harness 为运行底座，由大模型自主完成
   「任务规划 → 能力调用 → 反馈处理与结果验证」三步闭环，无需人工干预。

## 三、系统架构

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 物理仿真层 | `sim/`（config / geometry / thermal） | 有限差分二维稳态热传导，含网格收敛校验 |
| 优化层 | `opt/`（problem / searchers） | 约束建模 + 自适应邻域搜索 |
| 接口层 | `webapp.py` | FastAPI 网页操作台：滑块交互实时刷新温度场、一键自动寻优 |
| 工具层 | `mcp_server.py` | 6 个 MCP 工具（stdio 传输），把仿真与优化能力暴露给智能体 |
| 智能体层 | Agnes Harness | 任务规划、工具编排、结果验证、会话留痕 |

MCP 工具层共 6 个工具：`get_problem_spec`、`simulate_design`、`search_designs`、
`render_temperature_field`、`verify_design`、`compare_methods`，全部声明为**只读**。

## 四、AGH 三步闭环（核心能力）

在 AGH daemon 上，大模型 `agnes-3.0-flash` 收到一句话任务后自动完成：

1. **任务规划**：解析「读取问题定义 → 自适应搜索 → 复核设计」的意图，编排工具调用顺序；
2. **能力调用**：依次调用 MCP 工具（实测耗时：`get_problem_spec` 14 ms →
   `search_designs` 263 ms → `verify_design` 27 ms）；
3. **反馈处理与结果验证**：解析工具返回，判定网格无关性并生成最终设计报告。

**免批准机制**：6 个工具均声明 `read_only_hint`，AGH 据此判定
`isReadOnly=true / isDestructive=false / requiresApproval="never"`，因此工具调用
**全程无需人工批准**。会话导出文件中三次 `tool/call` 事件均为 `requiresApproval:"never"`，
且无任何 `rejected` / `user_rejected` 记录。

## 五、关键实测结果

- **最优设计**：翅片数 13，翅高 30.7 mm，翅片厚 2.0 mm，基板厚 2.0 mm；
- **性能**：热阻 `R_th = 1.551 °C/W`（粗网格 1.5508；细网格 240×200 为 1.540，相对偏差 0.7%）；
- **约束**：质量 149.69 g ≤ 150 g，结温满足 ≤ 85 °C；
- **复核**：网格无关性通过（相对偏差 0.007 < 0.05）。

## 七、技术亮点

1. **自研求解器 + 约束闭环**：不止单点计算，而是把三类工程约束纳入搜索闭环；
2. **「仿真能力即工具」**：以 MCP 把物理仿真/优化能力标准化暴露，实现 LLM 驱动的工程设计闭环；
3. **只读声明带来免批准自动执行**：在保证安全的前提下实现全自动工具调用；
4. **全链路可交付**：绿色版免安装 Python、双击即用，附带源码、运行证据与测试用例。

## 八、依赖与边界（如实说明）

- 模型调用由 AGH 底座完成，依赖：AGH 运行底座（Node.js ≥ 24.10）、本机模型凭据与本机联网；
  这些**不在安装包内**，换机需重新配置凭据。
- MCP 服务的注册 / 启用需在 AGH 控制台（或交互式终端）中确认，命令行非交互方式会因安全策略
  拒绝（fail-closed），属预期设计。
- 网页操作台与 MCP 工具层本身为本地计算程序，不依赖联网、不调用任何大模型。
